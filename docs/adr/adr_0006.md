# ADR-0006: Впровадження безперервного розгортання (CD) та стеку спостережуваності (Prometheus, Grafana, Alerting)

- **Дата:** 2026-11-25
- **Статус:** Прийнято (Accepted)

## Контекст
Після налаштування конвеєра безперервної інтеграції (CI) та автоматизованого розгортання хмарної інфраструктури в Microsoft Azure (Terraform + Ansible) виникла потреба у:
1. Автоматичній доставці перевірених Docker-образів із GitHub Container Registry (GHCR) на продакшн-сервер без ручних втручань та верифікації успішності релізу (Smoke Test).
2. Безперервному моніторингу стану хостової ОС, Docker-контейнерів та ключових показників роботи вебзастосунку за методологією RED (Rate, Errors, Duration).
3. Контролі обсягу журналів контейнерів для запобігання вичерпанню дискового простору.
4. Автоматичному сповіщенні адміністратора в реальному часі у разі деградації або падіння сервісів.

## Рішення
1. **Continuous Deployment (GitHub Actions):**
   - Розширено файл `.github/workflows/ci.yml` етапом `deploy`, який запускається виключно при злитті змін у захищену гілку `main` після успішного проходження етапів `lint`, `test`, `security-fs` та `build-and-push`.
   - Конвеєр передає `docker-compose.prod.yml` та конфігурації моніторингу на Azure VM через `scp`, формує `.env` із незмінним тегом образу `sha-<short_sha>`, виконує `docker compose -f docker-compose.prod.yml pull && up -d --remove-orphans` та перевіряє доступність сервісу запитом на `/healthz` (очікуваний статус `HTTP 200 OK`).
2. **Стек спостережуваності (Observability):**
   - У `docker-compose.prod.yml` додано ізольовану мережу `monitoring-net` та сервіси **Prometheus** (`v2.55.1`), **Node Exporter** (`v1.8.2`), **cAdvisor** (`v0.49.1`) і **Grafana** (`11.3.0`) з автоматичним провіжинінгом джерела даних (`monitoring/grafana/provisioning/datasources/prometheus.yml`).
   - У `backend/src/index.ts` реалізовано ендпоінт `/metrics` у форматі OpenMetrics/Prometheus для збору лічильників HTTP-запитів (`http_requests_total`), кодів відповідей та гістограми затримок (`http_request_duration_seconds`).
   - Для всіх контейнерів налаштовано ротацію логів Docker (`driver: json-file`, `max-size: 10m`, `max-file: 3`).
3. **Alerting (Grafana + Telegram):**
   - Налаштовано канал сповіщень (Contact Point) через Telegram Bot API та правило тривоги `StudShare Backend Down` (`up{job="studshare-backend"} < 1`) із періодом перевірки `10s` і затримкою підтвердження `30s`.

## Наслідки
- **Позитивні:** Повністю усунуто ручний деплой; кожен коміт у `main` автоматично проходить перевірки якості, безпеки та розгортається в продакшн із підтвердженням працездатності; час виявлення відмови сервісу (MTTD) становить ~40 секунд.
